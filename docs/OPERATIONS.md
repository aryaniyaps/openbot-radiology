# Local hospital operations

The current system is the KVM VM `kauvery-hospital` at 192.168.178.10 and six native OpenMausBot rootless Podman workstations. The VM and its network autostart. Docker services restart inside the VM. The host workstation timer recreates stopped native desktops once per host boot through the supported paired OpenMausBot API, repairs application/trust/graphics assets, and renews read-only browser sessions after hospital restart or desktop recreation while assistants are idle. Its operator pairing credential is root-only and renews through native pairing before expiry. The app must be running for native desktop preparation; the timer retries when it becomes available.

Run `python3 scripts/demo-stack.py status` for readiness, image counts, disk reserve and backup age. The configured app opens automatically when Aryan signs into the Linux desktop. You can also start it with `scripts/launch-packaged-demo.sh` from that desktop. Package installation is an operator task: `kauvery-demo` deliberately cannot run sudo apt. The original sudo denial was a privilege boundary, not a package lock held by another process.

Run `sudo -n python3 scripts/operations/backup.py` for an encrypted consistent backup. Nightly `kauvery-backup.timer` runs at approximately 02:30; it defers if an assistant is active or waiting for a teammate, and retries after 15 minutes. It pauses workstations, shuts down the hospital gracefully, copies the cold VM disk and assistant data, and restarts services. Retention is seven daily and four weekly snapshots. Keep at least 30 GiB free. Check status after a deferred job.

Repository: `/var/backups/kauvery-hospital/restic`. Encryption key: `/var/lib/kauvery-hospital/backup/restic-password`, root-only, deliberately excluded from the repository. Export the key separately and copy the repository to an external drive for disk-failure protection. **External-drive protection is not configured yet.**

`sudo -n python3 scripts/operations/restore-check.py` performs an isolated boot with no external network interface. The retained latest restore VM `kauvery-restore-check` is shut off; its existing target is protected against overwrite. See `docs/evidence/local-hospital/restore.json` for the passing cold restore: 17 studies, 1016 instances, seven report notes, all six native profiles and browser preferences, Codex authentication and an integrity-checked message database, in approximately two minutes. The first clone was removed only after its passing receipt was preserved. Use `scripts/operations/clean-restore-check.py` to remove a verified shut-off clone before repeating.

Private credentials and deployment environment live in `.private/server/`; do not publish them. `config/server/compose.yaml` contains pinned image digests and required secret placeholders; `secrets.env.example` lists variables. The running configuration is `/opt/kauvery-hospital/compose.yaml` inside the VM. Operator SSH uses `.private/server/operator-key`. TLS CA private keys must stay private.

The old project containers were removed only after restore proof; their volumes and rollback inspection are preserved. Obsolete source and recordings are archived outside this checkout under `/home/aryan/.local/share/openbot-radiology/repo-cleanup/`; they are excluded from Git. Other host applications were preserved.

Bahmni's DCM4CHEE5 bridge comes from upstream BAH-4353, not a released default profile. The pinned configuration and native worklist/C-STORE demonstrations qualify this local setup; upstream upgrades need equivalent checks. DICOM upload is limited to the VM scanner emulator. Assistants have native read-only hospital permissions. No signature extension or independent image diagnosis is provided.
